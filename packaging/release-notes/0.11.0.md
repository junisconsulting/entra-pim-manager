# Entra PIM Manager 0.11.0

More time on a role that is about to run out, and an active role that finally says where it applies.

## New

- **Extend time.** An activation that is running low no longer has to be watched, lost and
  requested again from the list: the ↻ button on every ACTIVE row — and on the expiry warning —
  opens the activation panel for exactly that role. Be aware of what it does, because PIM leaves
  no alternative: **there is no way to lengthen a running activation.** Microsoft's API refuses a
  second activation of a role you still hold, whatever end time you ask for, and the portal has no
  button for it either. So this one ends the running activation and immediately requests a new one
  for the full duration. You lose the role in between — usually seconds, occasionally a few
  minutes while PIM lets go — and the panel says so before you submit.
- **It comes prefilled.** For an Azure role the subscription or management group the expiring
  activation runs on is already ticked, and the justification is the one you gave last time with
  `- extend time` appended. Both are yours to change. The reason is remembered only while the app
  runs, and never written to disk — after a restart, or for a role activated elsewhere, the field
  starts empty.
- **Roles that need approval do not offer it.** Ending the activation would leave you waiting for
  an approver with no access at all, so the app says that instead of doing it.

## Changed

- **An active role now names its user, tenant and scope on separate lines**, instead of one line
  that ran out of room. A subscription called `lz-adp-poc` used to read `lz-a…`, which is no help
  when two of them differ in the tenth character. Long names wrap now rather than being cut — in
  the ACTIVE list, in the eligibility list, and in the scope picker.
- **A directory role confined to an administrative unit or a single app registration finally says
  so.** Until now it looked exactly like the tenant-wide role of the same name: "User
  Administrator" over one administrative unit and "User Administrator" over everything read
  identically. Both lists now name the scope — `Administrative unit: Seattle`, `App registration:
  Contoso Payroll` — resolved to the real display name rather than an object id.
- **A resource-group-scoped Azure role reads as `subscription/resource-group`**, because an
  `rg-prod` exists in half of them.

## Fixed

- **A deactivation could report success while the role was still active.** A network hiccup during
  the confirmation made the role look gone — the app read an empty list as "not there" rather than
  "could not check". It now tells those two apart, and the stop button only claims success when
  Microsoft has actually confirmed it. The same mistake is what an extension relied on to decide
  the role had been released.

## Notes

- No new permission and no admin consent. Scope names come from expanding data the existing role
  reads already return; a tenant that declines that expansion falls back to the object id and
  keeps working.
- Extending is a **new activation**, with its own justification and its own entry in the audit
  log. PIM allows back-to-back activations by design — the maximum duration is a ceiling per
  activation, not per day — so this changes nothing about what your role settings permit.
- Upgrading in place: nothing to re-enter, no new permissions. Accounts, pinned roles, saved
  justifications and scope sets carry over as always.
