# Entra PIM Manager 0.5.0

One click now answers the support question "is it the tool, or is it your network?" — Settings
gained a network check that probes every Microsoft endpoint sign-in actually needs.

## New

- **Network check in Settings → Diagnostics.** Probes the endpoints this app *and the Windows
  sign-in window* need — login authority, sign-in page CDN, device authentication, Microsoft
  Graph, and the update feed — per configured cloud, all over HTTPS/443. Each endpoint gets a
  green or red dot with a precise failure classification: DNS failure, blocked (connection
  refused), timeout, or TLS failure. Built for a real field case: in locked-down networks the
  sign-in window opens but stays blank, while device-code login works — because the sign-in
  *page* loads from CDN hosts (`aadcdn.msauth.cn` and friends) that firewalls often block while
  the token endpoint stays reachable. A red row is definitive evidence the endpoint is blocked
  from that machine.
- **TLS inspection is called out by name.** When a corporate proxy breaks the TLS handshake, the
  check captures the certificate issuer it saw (e.g. `CN=CorpProxy CA`) and says "likely TLS
  inspection" — the single most common cause of a blank sign-in window, now visible without a
  network trace.
- **Copy report.** One button puts a plain-text summary on the clipboard for a support ticket:
  hostnames, statuses, latencies, the proxy the app would use, app and OS version. No account
  names, no tokens, no proxy credentials — safe to paste anywhere.

## Notes

- The endpoint catalog follows Microsoft's official *URLs and IP address ranges* lists (worldwide
  and 21Vianet editions) plus the Azure China device-registration requirements. For Entra China,
  Microsoft requires the *global* login host too — the check covers that trap.
- The Windows sign-in window (WAM) runs out-of-process, so a green result cannot fully guarantee
  its own requests succeed — but red rows are proof of blocking, which is the answer that matters
  in a support case.
- Upgrading in place: nothing to re-enter, no new permissions, no admin consent — the check uses
  only anonymous requests.
