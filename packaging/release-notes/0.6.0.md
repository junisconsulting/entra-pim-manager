# Entra PIM Manager 0.6.0

Updates now arrive a little later — on purpose. This release makes auto-update safe in
locked-down corporate environments.

## Changed

- **Updates are offered only once a release is at least 72 hours old.** Here is why: our
  releases are currently not code-signed, and modern endpoint protection (for example Microsoft
  Defender's Attack Surface Reduction rules) treats a brand-new, unsigned program as untrusted
  until its file hash has been seen in the wild for roughly a day. If your app installed an
  update inside that window, Windows could refuse to start it afterwards — the app would look
  broken even though nothing is wrong with it. We saw exactly this happen in a customer
  environment. Waiting 72 hours means that by the time your app offers an update, the release
  has already built up reputation and installs cleanly. You trade a little speed for never
  ending up with an app that won't launch. Once our releases are code-signed (planned), this
  waiting period can go away.
- **The manual "Check for updates" button is gone.** The background check (once a day) covers
  the normal case, and the button was the one path that could still fetch a release younger
  than the safety window. If you ever need a specific version immediately, the installer on the
  GitHub Releases page always works.

## Notes

- The waiting period is enforced by this version's updater, so it protects all updates *from*
  0.6.0 onward. The update *to* 0.6.0 itself still uses the previous behaviour — if your
  environment blocks fresh binaries, simply accept the update prompt a day or two after the
  release date.
- If the release age cannot be determined (for example, no connection to the GitHub API), the
  update is deferred to the next daily check rather than offered blindly.
- Upgrading in place: nothing to re-enter, no new permissions, no admin consent.
