# Entra PIM Manager 0.7.0

**Check Settings → App Registration once after this update.** App Registrations are now
configured per tenant, and your existing setup is converted automatically: every tenant you
were signed in to (and every tenant on your allow-list) becomes an entry with the client id you
used there, and no account has to sign in again. Only a client id that had *no* signed-in
account and no allow-list entry cannot be converted — it is removed, and you add it again
together with its tenant id.

This release exists for one customer requirement: a single-tenant App Registration next to the
multi-tenant one, i.e. several App Registrations in the same cloud.

## Added

- **One App Registration per tenant.** Settings → APP REGISTRATION lists one entry per tenant:
  tenant id, client id, cloud, and an optional label. A multi-tenant registration used in
  several tenants is listed once per tenant with the same client id; a customer's own
  single-tenant registration is simply another entry. Click a row to edit it in place; the
  cloud is shown as a colour-coded chip, and each entry shows whether an account has already
  signed in through it.
- **Labels.** The label you give an entry names the tenant everywhere — the "Sign in with"
  picker, the eligibility list, the active list and the accounts list — instead of the
  directory's display name.
- **Log detail setting** under Settings → Diagnostics: *Debug*, *Normal* or *Warnings only*,
  applied immediately. *Normal* keeps the app's own activity and drops the sign-in library's
  wire chatter, which used to fill a day's log file to around 250 MB; *Debug* restores it for
  troubleshooting sign-in problems.
- **Tenants without a PIM licence are named as such.** A tenant without Entra ID P2 or
  Governance no longer looks like an empty "(0)" — the group shows a warning explaining why
  nothing can be activated there.

## Changed

- **Adding an account starts from the list.** The add-account panel offers the configured
  tenants under "Sign in with" instead of a free-text tenant field; a tenant needs an entry
  before you can sign in to it. The list is therefore also the allow-list — the separate
  `AllowedTenants` setting is folded into it.
- Log files are kept for 7 days instead of 14.

## Fixed

- **The in-app Restart button works again.** The replacement instance used to see the old
  one as "already running" and quit, leaving nothing running. It now waits for the old
  process to exit before taking over.

## Notes

- Upgrading in place: no new permissions, no admin consent. Sign-ins carry over — the token
  caches are renamed per App Registration on first start.
- In `%LocalAppData%\junis\Entra-PIM-Manager\appsettings.local.json`, the keys
  `AppRegistrations`, `ClientId` and `AllowedTenants` are replaced by `TenantAppRegistrations`
  on first start. The full setup, including the single-tenant case, is described in
  `docs/app-registration-setup.md`.
- A single-tenant registration needs the same redirect URI and "Allow public client flows"
  setting as the multi-tenant one; admin consent is granted per tenant.
