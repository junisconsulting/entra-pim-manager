# Entra PIM Manager 0.10.0

Activate an Azure role on just the subscriptions you need, and roll the app out without anyone
typing a client id.

## New

- **Narrow an Azure activation to selected scopes.** An Azure resource role you hold on a
  management group no longer has to be activated on everything beneath it. The activation panel
  gets an **Activate on** picker: search at the top, then the subscriptions, then the management
  groups, and at the very bottom the entire scope. Every tick becomes its own activation, so the
  ACTIVE list shows one row per subscription and each can be ended on its own. This is what the
  portal's "Scope" tab does; resource groups are deliberately not offered.
- **Nothing is preselected, on purpose.** The picker starts empty and Activate says so until you
  answer it — including when the answer is the entire management group, which now takes one
  deliberate tick at the bottom of the list. Taking everything should be a decision, not what
  happens when you leave a form alone.
- **Save a set of scopes and star it.** A ticked selection can be saved under a name of your
  choice ("Project X"). Saved sets sit in the activation panel for that role, and a starred one
  also sits under PINNED on the main page next to your pinned roles: one click opens the panel
  with exactly those scopes ticked, and Activate does the rest. The star works the same way on
  both, so pinning a role and pinning a scope set are one idea, not two. Sets live in a file
  of their own on this machine (`scope-favorites.json`), never in the tenant.
- **Unattended deployment.** Rolling the app out to a team no longer means walking every user
  through Settings → TENANTS. `scripts/create-app-registration.ps1` creates the App Registration,
  requests the permissions and grants consent once per tenant, then prints the endpoint commands
  with the real ids filled in. `scripts/install-entra-pim-manager.ps1` runs on the endpoint: a
  silent install, then the app itself writes the tenant entry and exits — so an Intune install
  command actually returns, which a tray app otherwise never would. It then verifies the entry
  landed in the config rather than trusting the exit code. The full procedure, including the two
  raw commands for deployment tools that cannot run a script, is in
  [docs/unattended-deployment.md](https://github.com/junisconsulting/entra-pim-manager/blob/main/docs/unattended-deployment.md).

## Changed

- **The tray icon now carries the junis colours** — yellow on dark blue, drawn so the two contrast
  against each other rather than against the taskbar. The key is drawn in blue instead of being cut
  out of the shield, which is what made it disappear on a light taskbar. The four status colours
  and their meaning are unchanged.
- **The stop button stays grey for the first five minutes** of an activation and only turns red
  once it works. Microsoft refuses a deactivation inside that window, and the button was already
  disabled — now its colour says the same thing instead of the opposite.

## Notes

- No new permission and no admin consent: the scope list comes through the same Azure Service
  Management permission 0.9.0 already uses.
- **Azure roles held on a management group need one extra click now**: the scope. Everything
  else — directory roles, PIM for Groups, and Azure roles held directly on a subscription — is
  unchanged. A selection is a decision per activation and is never carried over to the next one.
- The picker walks your management-group hierarchy, so subscriptions under nested management
  groups are listed too. If one you expect is missing, please report it with the management
  group it sits under.
- Upgrading in place: nothing to re-enter, no new permissions. Your accounts, pinned roles and
  saved justifications carry over as always.
