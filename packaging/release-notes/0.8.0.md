# Entra PIM Manager 0.8.0

**Add the delegated permission `RoleManagementPolicy.Read.AzureADGroup` to your App
Registration and grant admin consent again — in every tenant — before you roll out this
update.** The app now requests that scope at sign-in. In a tenant that has not consented to it,
the sign-in stops being silent: the WAM prompt reappears and asks for consent, which only an
admin can give. The permission is read-only; it is what lets the app read a group's PIM
settings, and the `.Directory` variant already in the list does not cover groups.

This release fixes PIM for Groups activation, which could not be started at all.

## Fixed

- **Clicking an eligible group opens the activation window again.** Reading the group's PIM
  settings needs its own permission, which the app never asked for, so Microsoft refused the
  read with "missing permission scope RoleManagementPolicy.Read.AzureADGroup". The click ended
  there: the spinner turned briefly and nothing else happened. Directory roles were unaffected,
  which is why only groups looked broken.
- **A group's member settings are no longer confused with its owner settings.** Membership and
  ownership of the same group carry independent PIM settings — maximum duration, justification,
  MFA, approval — and the app read whichever of the two Microsoft happened to return first. The
  activation window could therefore offer the wrong duration or ask for the wrong things.
- **A failed click says why, in the list itself.** The reason used to be a Windows notification
  only, which Focus Assist and Do-Not-Disturb swallow without a trace — the click then looked
  ignored. It now also appears as red text under the row, the same way a failed deactivation
  already did. A tenant that is missing consent for the App Registration is named as such
  instead of "see the log file".

## Notes

- Until a tenant's consent is renewed, group activation still works: the activation window
  opens with conservative defaults (8 hours, justification required) and Microsoft enforces the
  tenant's real rules on the request itself. The log records
  `Policy read failed ... Using default activation limits` in that case.
- The full permission list is in `docs/app-registration-setup.md`; the per-tenant consent URL
  for a multi-tenant registration is in the same file.
