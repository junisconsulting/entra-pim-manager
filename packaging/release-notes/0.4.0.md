# Entra PIM Manager 0.4.0

Role activations protected by Conditional Access now work end to end.

## New

- **Step-up verification for protected roles.** Roles guarded by a Conditional Access **authentication context** now activate properly: the app requests a token that satisfies the required context, and Windows prompts for verification (Hello, FIDO2, Authenticator) when needed — the same flow the Azure portal uses. Previously, clicking Activate on such a role silently did nothing.

## Fixed

- **Activation errors are no longer silent.** Any failure during activation now stays visible inside the activation panel instead of closing it with only a toast that Focus Assist may suppress. The **Validate** pre-check no longer reports success when the dry-run actually failed, and cancelling the Windows verification prompt shows a clear message instead of a generic error.
- **Updates no longer collide with your data.** App data (accounts, settings, token cache, logs) moved out of the installer's application directory to `%LocalAppData%\junis\Entra-PIM-Manager`; existing data is migrated automatically on first start. This fixes the "Failed to remove existing application directory" setup error and prevents data loss during Setup-driven updates.

## Notes

- Graph/PIM errors are now recorded in the log file with their error code, HTTP status, and request id, making diagnostics much easier.
- Updating from an older version via the built-in updater preserves all data. Running the Setup installer manually over version 0.3.0 or earlier requires closing the app first.
